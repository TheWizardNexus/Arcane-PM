Docs / Storage & cleanup
Proposed storage model

Keep files with their owner.

Application records and project working files have different homes, lifecycles, and reasons to stay.

File ownership

OwnerIntended content
DBOPFSArcane PM application records and model assets.
Project foldersWorking documents, source files, and other files used by the project’s normal tools.
CodexNative conversations and its own project-access state.

A task record retains the assignment, decisions, open questions, selected originals, prepared results, and actual delivery state. Commentary and source content keep separate roles.

Archive a task

Archiving is intended to remove a task from the active view while keeping its record retrievable. Original project files and Codex chats remain preserved. An archived label does not mean the task’s working files are disposable.

Review disposable files

Deletion is a separate action for specifically selected generated material whose purpose has ended. The interface should identify what will be removed and what remains. Files still needed by another task stay with their owner.

The application root remains the repository root. The intentionally public website and documentation live in site/. Application records and private working content do not belong in that public directory.

The exact storage layout, persistence behavior, model-asset handling, and any import or export operations remain to be documented from their implementation.
