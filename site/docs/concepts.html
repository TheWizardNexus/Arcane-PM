Proposed application model

A shared language for the work.

Projects give work a home. Tasks give it a purpose. Handoffs carry what the next person or worker needs.

The building blocks

Project
A home for related work and the files its usual tools already use.
Task
An assignment with a recognizable face, its current state, decisions, and open questions. The face helps you recognize the work; the text explains it.
Preparation
Research, selected source material, or a draft assembled for an assignment. Preparation can remain useful while its destination is unavailable.
Handoff
A defined assignment and its supporting context, selected for another task or project.

Name the actual state

A prepared handoff is ready. It becomes accepted only when its destination confirms acceptance. Starting the assignment and completing its work are further, separate events.

That distinction keeps a polished draft from being mistaken for delivered work. The proposed task record keeps preparation, delivery, and execution visible without asking a face or a colored dot to carry the whole meaning.

Archiving changes the active view. Deleting selected disposable files changes what is stored. Storage and cleanup explains their different effects.

Run the application locally

With Node.js and npm available, run these commands from the application repository root:

npm i
npm run dev

Open http://127.0.0.1:4310/index.html. The development command serves the application’s source and composes its declared local host services. Native Codex access, native ONNX execution, and native image generation need that running Arcane PM host and their respective runtime readiness.

The application declares arcane-os as latest; the retained lockfile records the selected SDK version. A dependency refresh uses the coordinated application-owned workflow, including npm update arcane-os and comparison of the installed and locked versions with the published channel before generation or packaging.

PWA and browser packaging

package.pwa in arcane-app.json owns the application’s PWA metadata and icon selection. Refresh its managed import map and PWA files through the installed SDK:

npm run import-map -- --app arcane-pm

The generated root files are arcane.webmanifest, arcane-offline.json, arcane-sw.js, and arcane-pwa.mjs. Keep these generated files committed; change their authored configuration and regenerate through the SDK.

For a selected browser artifact, package the application, then verify that output:

npm exec -- arcane package --app arcane-pm
npm exec -- arcane verify --app arcane-pm

The browser output is dist/arcane-pm. The application composition owner recorded successful packaging and verification with SDK 0.69.0, followed by a browser reload that retained the shell, styles, guide image, and navigation after its package preview server stopped. That observation covers those cached browser resources; native services and native model execution still depend on their running host.

Installation is controlled by the browser. Use its install action when offered; actual installation remains unverified. A static browser package supplies no native host. Native executable targets remain separate work.

The repository’s arcane-pm-app package is private application setup. The reusable public npm package, installation contract, callable API, and exported component library remain separate work.
