Docs / Project bridge
Proposed integration

Connect projects. Keep ownership clear.

A decoupled bridge is intended to connect Arcane PM’s task context with Codex through supported public interfaces.

Arcane PM owns assignments, preparation, decisions, and its surrounding interface. Codex retains ownership of native project access, conversations, and execution. Working files remain with their system project folders.

The intended flow

  1. Choose the destination project and task.
  2. Prepare the assignment, decisions, open questions, and complete selected sources.
  3. Send through the supported bridge.
  4. Record the destination’s actual acceptance or failure response.

A destination that is unavailable leaves the handoff ready, with its prepared content available. Acceptance, reading, work starting, and completion remain distinct outcomes.

Account context belongs to its owner

An Arcane PM account switch changes the context used by Arcane PM. Native Codex access has its own state. The application should show both accurately; switching one is not evidence that the other has changed identity or signed in.

Implementation boundary

Native Codex access requires the running Arcane PM host. In the recorded packaged-browser check, the application composition owner observed Connections reporting that requirement and leaving Connect unavailable. See local setup for the source-host command. The reusable public bridge API and platform coverage remain under development; Windows, Linux, and macOS are the intended desktop targets, with host adaptation only where needed.

Start with a complete context handoff; keep it useful independently of its delivery mechanism.
