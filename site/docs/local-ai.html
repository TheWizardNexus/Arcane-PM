Integration requirements

Prepare locally. Let the model owner run the model.

Arcane PM owns the purpose of the work. The Arcane SDK owns reusable model execution and lifecycle.

Planned AI work includes finding relevant material, organizing context, developing a task plan, and generating task-worker faces. These are application workflows composed through supported SDK interfaces.

Intended runtime scope

The requirements include Jev, ONNX, llama.cpp, Ollama, and optional DigitalOcean inference. This list expresses intended support. Available models, concrete adapters, host requirements, and execution behavior still need to be established in Arcane PM.

Readiness belongs at inference

The planned interface acknowledges a request immediately and observes the model owner’s state. Inference starts when the exact selected provider and model are ready and loaded. Project browsing, record reading, and task preparation remain usable while a model loads.

If the selected model unloads, fails, or changes before a response commits, its request must stop and observe the next authoritative ready state. Windows, Linux, and macOS remain intended desktop targets; each runtime’s actual availability needs its own evidence.

Complete inputs and responses

Selected source content reaches the operation unchanged. Instructions and routing information travel separately. Visible response chunks appear in order as they arrive; cancellation and genuine failure remain visible in the owning task surface.

Development is intended to follow the published SDK’s latest channel. An implementation reference will identify the public interfaces actually adopted and their observed behavior.
